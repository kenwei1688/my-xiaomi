# 生活小秘 · 后端公有云部署指南（同源完整部署）

> 目标：把 `server/` 部署到任意能运行 Node 的云主机，实现**前后端同源**——
> 单个 Node 进程同时提供 API（`/api/*`）与静态前端（`../app`），天然免 CORS，
> H5 与 Android 开箱即用，无需手动填写服务器地址。

---

## 一、为什么是"同源"

`server/server.js` 已内置静态托管（`STATIC_DIR = ../app` + `serveStatic`）：

```
浏览器/WebView ── 同一端口(默认 3000) ──▶ Node 单进程
   GET  /                → app/index.html  (前端)
   GET  /js/api.js       → app 静态资源
   GET  /api/health      → API
   POST /api/auth/login  → API
```

- 前端与后端**同 origin**，H5 直接用相对路径 `/api/...` 请求，无跨域问题。
- Android 内 WebView 加载同源前端，登录后自动把"页面 origin"交给原生 `setCloudConfig`（已修复同源时空 server 的 bug）。
- 只需一台 Node 主机，无需 Nginx 反代即可工作（HTTPS 时再加 Nginx）。

---

## 二、前置条件

| 项 | 要求 |
|----|------|
| 云主机 | 任意 VPS（腾讯云/阿里云轻量 2核2G 起，约 ¥50-100/月），Ubuntu 20.04+ / Debian 11+ |
| Node | **≥ 18**（Docker 镜像内置 Node 22；systemd 方式需自备） |
| 域名 | 可选；有域名 + 已备案可做 HTTPS |
| 开放端口 | 3000（直连）或 80/443（经 Nginx 反代） |

> 后端**零第三方依赖**，无需 `npm install`，拷贝即用。

---

## 三、方式一：Docker 一键部署（推荐）

`deploy/` 已提供完整脚本（Dockerfile + docker-compose + nginx + systemd + 一键脚本）。

```bash
# 1. 把项目根目录（含 app/ server/ deploy/）上传到服务器
#    scp -r ./ 项目根 root@服务器IP:/opt/lexiang-life
ssh root@服务器IP
cd /opt/lexiang-life

# 2. （强烈建议）设置 JWT_SECRET，避免 token 被伪造
cd server
cp .env.example .env
# 生成随机密钥并写入 .env（把下面的输出粘进 .env 的 JWT_SECRET）
openssl rand -base64 48
vi .env            # 修改 JWT_SECRET=你的随机串；PORT 保持 3000
cd ..

# 3. 一键部署：装 Docker → 构建镜像 → 启动 → 可选 HTTPS
sudo bash deploy/deploy.sh
```

脚本完成后访问 `http://服务器IP:3000` 即为同源前端，`/api/health` 为 API 文档。

> 同源部署时前端已随镜像一起托管，**无需**再单独部署 CloudStudio 静态站；
> 若仍保留静态站，会把用户引到无后端的前端（只有演示数据），建议下线或改指同源地址。

## 四、方式二：systemd 免 Docker

```bash
ssh root@服务器IP
# 1. 安装 Node 22
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt-get install -y nodejs

# 2. 上传项目到 /opt/lexiang-life（保留 app/ server/）
cd /opt/lexiang-life/server
cp .env.example .env && vi .env   # 设置 JWT_SECRET

# 3. 注册并启动服务（自动守护 + 开机自启）
cp deploy/lexiang.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now lexiang

# 4. 验证
curl http://127.0.0.1:3000/api/health
```

`deploy/lexiang.service` 已配置 `WorkingDirectory=/opt/lexiang-life/server` 与
`ExecStart=/usr/bin/node server.js`，并设 `Restart=on-failure`。

---

## 五、必改项：JWT_SECRET（安全红线）

Token 用 HMAC-SHA256 签名，`auth.js` 取 `process.env.JWT_SECRET || 'life-secret-change-me-in-prod'`。
**生产必须用环境变量或 `.env` 覆盖默认值**，否则任何人都能伪造登录态。

```bash
# 方式 A：.env 文件（推荐，server.js 已内置零依赖加载器）
JWT_SECRET=$(openssl rand -base64 48)   # 写进 server/.env

# 方式 B：真实环境变量
export JWT_SECRET="你的随机长字符串"
node server/server.js
```

## 六、防火墙与安全组

- 云厂商**安全组**放行：`3000`（直连）或 `80/443`（Nginx 反代）。
- 若用 Nginx 反代到 443，建议安全组**只开 80/443，关闭 3000 公网直连**，由 Nginx 内网转发。
- SSH：禁用密码登录、用密钥；可装 `fail2ban` 防爆破。

---

## 七、验证部署

```bash
# API
curl http://服务器IP:3000/api/health
# 应返回 {"status":"ok","persistent":true,...}

# 同源前端
curl -s -o /dev/null -w "%{http_code}" http://服务器IP:3000/
# 应返回 200（index.html）

# 注册→登录→拉提醒（串联验证）
curl -s -X POST http://服务器IP:3000/api/auth/register -H 'Content-Type: application/json' \
  -d '{"identifier":"demo","password":"demo123"}'   # 返回 {token,user}
```

## 八、数据持久化与备份

- 数据落在 **`server/data/db.json`**（用户 / 提醒 / 行程，按 userId 隔离），重启不丢。
- **切勿在运行时删除该文件**；升级时保留它。
- 备份示例（cron 每日）：
  ```bash
  0 4 * * * tar -czf /backup/lexiang-$(date +%F).tar.gz -C /opt/lexiang-life/server data
  ```
- 容器部署时，建议把 `server/data` 挂到命名卷（`lexiang-data`），见 `deploy/README.md`。

---

## 九、HTTPS（可选，生产建议）

1. 域名 A 记录解析到服务器 IP，并完成 ICP 备案（大陆服务器必需）。
2. `deploy/deploy.sh` 会交互询问域名并自动申请 Let's Encrypt 证书（certbot）。
3. 或手动：`apt install nginx certbot python3-certbot-nginx` → 用 `deploy/nginx.conf` 反代 3000 → `certbot --nginx -d 你的域名`。

> Android 端 `AndroidManifest` 设了 `usesCleartextTraffic=true`，允许 http 调试；
> 生产建议全 HTTPS，并在客户端校验证书。

---

## 十、同源下的客户端行为（已对齐）

- **H5**：`serverUrl` 为空时自动用相对路径 `/api/...`，**无需手动填服务器地址**。
- **Android**：WebView 加载同源前端；登录后 `afterCloudLogin` 把
  `window.location.origin` 传给原生 `setCloudConfig`（同源空 server 的 bug 已修），
  原生后台拉取 `/api/reminders` 并调度系统闹钟（关屏/杀进程仍响）。
- **退出登录**：H5 调用 `clearCloudConfig()`，原生回到纯本地调度。

---

## 十一、常见问题

| 现象 | 排查 |
|------|------|
| `curl /api/health` 不通 | 服务是否启动（`systemctl status lexiang` / `docker ps`）；端口/防火墙 |
| 前端打开是旧版 | 浏览器缓存，强刷；确认部署的是最新 `app/` |
| 登录后 Android 不响铃 | 检查原生日志 `CloudSync` 是否拿到非空 server/token；权限是否授予 |
| Token 莫名失效/被伪造 | 确认 `JWT_SECRET` 已设置且重启后一致（更换密钥会使所有旧 token 失效） |
| 数据"丢了" | 检查 `server/data/db.json` 是否被误删或容器卷未挂载 |

# 附录：Android APK 本地重建

> 本沙箱**无 Java / Gradle / Android SDK**，无法在此编译 APK。请在装有 Android Studio 的机器上执行。

### 前置
- JDK 17（与 `build.gradle` 的 `JavaVersion.VERSION_17` 一致）
- Android SDK（compileSdk 34 / minSdk 24），设置 `ANDROID_HOME` 或在 `local.properties` 写 `sdk.dir=...`
- 已联网（首次构建 Gradle 会下载依赖）

### 一键构建（Debug 包，可直接安装）
```bash
cd android-app
# Windows：
gradlew.bat assembleDebug
# macOS / Linux：
./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

### 构建 Release 包（上架用，需签名）
```bash
./gradlew assembleRelease
# 当前 build.gradle 的 release 复用 debug 签名；正式发布请配置自己的 keystore
```

### 本次已包含的改动（务必重新构建才生效）
- 新增 `CloudSync.kt`：后台拉取云端提醒并交给 `ReminderScheduler` 调度系统闹钟。
- `MainActivity` / `BootReceiver`：启动、回前台、设备重启触发云端同步。
- `NativeBridge.setCloudConfig / clearCloudConfig`：H5 登录/退出联动原生。
- **版本号已提升**：`versionCode 5`、`versionName "1.0.5"`（上版为 1.0.4）。

### 重建前自检清单
- [ ] `CloudSync.kt` 存在且 `ReminderScheduler` 引用正确
- [ ] `MainActivity.kt` 含 `setCloudConfig` / `clearCloudConfig` 与 `CloudSync.sync` 触发
- [ ] `AndroidManifest.xml` 权限齐全（INTERNET / RECEIVE_BOOT_COMPLETED / SCHEDULE_EXACT_ALARM / POST_NOTIFICATIONS / SEND_SMS）
- [ ] `local.properties` 的 `sdk.dir` 指向本机 SDK
