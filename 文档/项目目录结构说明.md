# 生活小秘 · 项目目录结构说明

> 版本 v1.0.4 · 2026-09-01 · 项目根目录 `D:\WorkBuddy\MyAssistantProject`

本文件说明项目根目录下每个文件夹的用途、关键文件，以及哪些「不能动」、哪些是「权威源码」、哪些是「副本/构建产物」。

---

## 一、根目录总览

```
MyAssistantProject/
├── .git / .gitignore          ← 版本控制元数据（保留根目录，不能动）
├── 后端源码/                   ← Node.js 后端服务（自包含 Railway 部署单元）
├── Android原生工程/            ← Android 原生 App 工程（Kotlin + WebView）
├── 小程序/                     ← 微信小程序源码
├── 文档/                       ← 部署/上线/同步等说明文档
├── 交付包/                     ← 全平台交付包（副本快照 + 打包 zip）
└── APK/                        ← 4 个 Android 安装包（v1.0.0 ~ v1.0.4）
```

> ⚠️ 说明：早期版本曾有一个独立的「部署配置/」目录，存放 `Dockerfile` / `railway.json` / `.railwayignore`。
> 现已**并入 `后端源码/`**（后端源码自包含部署配置，Railway 的 Root Directory 指向 `后端源码`），所以根目录不再有「部署配置/」这个文件夹。

## 二、后端源码/（权威后端 · Railway 部署源）

纯 Node.js 服务，运行时零外部依赖，入口 `start.js` → `server.js`，SQLite 持久化。

```
后端源码/
├── server.js                  ← 后端主入口（纯 Node http + REST API + 提醒调度器）
├── start.js                   ← 启动器（Node<24 自动加 --experimental-sqlite）
├── db.js                      ← SQLite 持久层（node:sqlite，多租户数据桶）
├── package.json               ← 包描述（type: module，Node >= 22.5）
├── .env.example               ← 环境变量示例（JWT / LLM / 供应商密钥等）
├── Dockerfile                 ← Railway 构建（node:22-alpine）
├── railway.json               ← Railway 服务配置（build/deploy/healthcheck）
├── .railwayignore             ← Railway 构建上下文排除清单
├── lib/                       ← 智能体核心模块
│   ├── engine.js              ←   智能体编排核心（意图识别 → 动作 → 回复）
│   ├── nlu.js                 ←   自然语言解析 + 北京时间时区工具
│   ├── auth.js                ←   JWT 鉴权（零依赖 HS256）
│   ├── booking.js             ←   下单/预订逻辑
│   ├── itinerary.js           ←   行程规划
│   ├── cities.js              ←   城市数据
│   └── providers/             ←   下单供应商适配层
│       ├── index.js           ←     供应商路由（mock/meituan/ctrip，环境变量切换）
│       ├── mock.js            ←     模拟下单（默认）
│       ├── meituan.js         ←     美团通道
│       └── ctrip.js           ←     携程通道
├── public/                    ← Web 前端（当前生效的前端）
│   ├── index.html             ←   前端主页
│   ├── app.js                 ←   前端逻辑
│   ├── styles.css             ←   前端样式
│   ├── admin.html             ←   管理页
│   ├── sw.js                  ←   Service Worker（PWA）
│   ├── manifest.webmanifest   ←   PWA 清单
│   └── icons/                 ←   图标
├── deploy/                    ← 传统部署方案（非 Railway，备用参考）
│   ├── deploy.sh              ←   一键部署脚本
│   ├── docker-compose.yml     ←   Docker Compose
│   ├── nginx.conf             ←   Nginx 反向代理
│   ├── lexiang.service        ←   systemd 服务
│   └── README.md              ←   部署说明
└── data/                      ← 运行期数据（SQLite 自动生成，不入 git）
    └── xiaomi.db              ←   SQLite 数据库文件
```

> ✅ 权威源码，git 跟踪。`data/xiaomi.db` 是运行期数据（`.gitignore` 已排除，不入库），首次启动自动创建。

    └── app/                   ← App 主模块
        ├── build.gradle       ← 模块构建（applicationId com.lexiang.life）

        └── src/main/

            │   ├── SplashActivity.kt      ← 启动页

## 八、三组「重复」关系速查（正本 vs 副本）

| 内容 | 根目录（正本/权威） | 交付包（副本/分发） | 能否删根目录 |
|------|--------------------|--------------------|-------------|
| 后端源码 | `后端源码/` | 交付包内 `后端源码/` | ❌ 不能 |
| Android 工程 | `Android原生工程/` | 交付包内 `Android原生工程/` | ❌ 不能 |
| 安装包 | `APK/` | 交付包内 `APK/` | ❌ 不能 |
| 小程序 | `小程序/` | 交付包内 `小程序/` | ❌ 不能 |
| 文档 | `文档/` | 交付包内 `文档/` | ❌ 不能 |

> 结论：根目录是唯一权威，交付包是它的副本快照，两者内容一致。日常开发/维护/部署用根目录；对外交付用交付包（zip）。
